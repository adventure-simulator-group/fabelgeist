## Exact GLB native layout and API

The current writer emits:

- 12-byte file header: magic glTF, version2 and total u32 byte length;
- 8-byte JSON chunk header: padded payload u32 length and JSON type word;
- JSON bytes padded with ASCII spaces to a multiple of4;
- 8-byte BIN header: padded payload u32 length and BIN type word;
- BIN bytes padded with zero bytes to a multiple of4, including current empty
 BIN-chunk behavior.

These are byte lengths, not element counts, vertices, dispatches or GPU buffer
quantities. Native chunk codes remain0x4E4F534A and0x004E4942, little-endian.
The total is28 plus both padded payload sizes; all three serialized lengths
must fit u32. Because total is4-aligned, the largest representable aligned
container total is u32::MAX-3; do not treat that as an unrelated configurable
cap or silently round down a too-large frame.

Recommended one owning private GlbLayout/packet constructor accepts the actual
serialized JSON byte length and actual BIN Vec length, checks four-byte padding
using checked host arithmetic, checks each complete addition, and performs
actual u32::try_from conversions for both padded chunks and the total. Retain
std::num::TryFromIntError as source for narrowing, with the exact field role
Json/Bin/Container. checked_add/rounding failure has no underlying std error:
return its own typed overflow variant with the actual operation/role, not a
fabricated conversion cause. Private immutable fields/readonly derived getters
keep total, chunks and padding coupled. No Default, serde or bypassing public
constructor. The writer consumes that one layout, not separately supplied raw
lengths or another legacy implementation.

Check layout BEFORE resize, capacity reserve, header construction and GLB file
operations. A native u32-valid size can exceed Vec allocation capacity on a
smaller host; fallible try_reserve_exact can preserve TryReserveError as an
actual source instead of inventing a byte ceiling or silently panicking on
capacity overflow. If allocation behavior is retained rather than made fallible,
state that limit explicitly; checked integer metadata alone does not prove
allocation success. Payload padding/reserve must not happen before its needed
layout check. Do not author a metadata-only test helper or new boundary case.

Keep glb.rs or a focused glb/layout.rs as the sole format owner, with a cohesive
GlbResult<T>/GlbError (or equivalently named) rather than widening a local error
to erase details. Minimum failure families: Serialize(serde_json::Error),
Layout(actual typed layout error), Reserve(TryReserveError) if used,
CreateDirectory{path,source:io::Error} and Write{path,source:io::Error}.
Existing profiling wrapper can retain the actual serialization/IO Result.
Current top export can consume `glb::write(...)?; Ok(())` into its mixed anyhow
Result, preserving typed sources; never Error::msg/to_string. Real file paths
are diagnostic native input, not closed enums or display classifiers.

Successful output must retain exact current JSON serialization order/values,
spaces/zeros, type/magic/version words, chunk order and all existing GLB fixture
oracles. Invalid metadata must fail before any GLB path is created/truncated or
written. This does NOT promise a transaction against later IO partial writes;
no temporary-file/rename/cleanup framework is requested.
