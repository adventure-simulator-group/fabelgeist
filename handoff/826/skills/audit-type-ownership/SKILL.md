# Type ownership

Map each affected concept to its definitions, dependency directions and users.
Search outside the diff for competing owners and overlapping migrations.

- Detect equivalent types maintained independently, wrappers borrowed for the
  wrong meaning, and owners placed above consumers that need to share them.
- Compare contracts before consolidating. Equal units or validation do not make
  different clocks, coordinate frames, identities or authorities
interchangeable.
- Separate a shared checked numeric leaf from useful role wrappers. Share the
  invariant without erasing a meaningful distinction.
- Identify the authoritative module and a coherent move/reuse plan. Preserve
  legitimate wire adapters; follow repository rules on compatibility paths.

Report both owners, their actual callers and the conflicting or duplicated
responsibility. Type granularity asks whether a distinction earns its place;
this lens asks where an established concept belongs and which owner is right.

Pin scope/revision; read applicable rules. Before repairs, finish this lens's
exhaustive pass and write an ignored ledger: source locations, contracts/traces,
dispositions, exact connected repairs and acceptance criteria. Account for every
scoped path; group only identical justifications. Untraced paths remain incomplete.
Review only unless fixes/publication are authorized. Distinguish defects,
migration gaps and suggestions.
