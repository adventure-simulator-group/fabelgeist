# Review shared grown tree meshes

The native tactical viewer has explicit `specimens` and `generated` modes. The
private specimen mode places three grounded instances of one admitted source
tree. It installs the selected mesh and material closure once, then shares the
handles between placements. The diagnostic checks actual indirect GPU draws and
compacted instance records before saving an image. Fixed captures hold one
explicit Full, Middle or Coarse level throughout the run. Full uses the
library's declared detail; Middle uses six tube sides, one span and six leaf
blades; Coarse uses four sides, one span and two blades. The same admitted
records and botanical source identity are used at every level.

Static specimen captures do not establish adaptive detail or arrival
performance. Generated mode uses the existing tree presenter and its actual
physical roots, with fixed or adaptive selection. The specimen commands and
isolation rules below apply only to specimen mode.

Broadleaf and needle normals follow their actual quad winding. The two-sided
fragment and normal prepass orient those normals to the visible face. This
shared geometry rule applies to both ordinary and instanced forest materials;
changing vertex encoding or detail level does not invert leaf lighting. The
separate curved-frond branch is outside this broadleaf/needle correction.

The real-world capture source label includes the grown renderer, growth,
scene-schema, math and seed owners. It remains a curated source label rather
than a complete transitive build fingerprint. Feature/build, executable, input,
bank and complete source pins remain separate evidence.

## Actual generated tactical roots

Generated mode takes two distinct actual botanical sources from one admitted
bank. Both must contain wood and leaves. It requests Address geometry through
`TreeContentRequest::Grown` before scene admission. It builds both sources at
Full, Middle and Coarse in the existing cache, sharing one bank upload owner. A
fixed capture holds the explicit selected level. An adaptive capture follows the
finite approach and retreat sequence described below. Its aggregate logical mesh
allowance is 256 MiB and the part vertex limit is 100,000. Neither limit
describes process or GPU memory.

```powershell
tactical-scene-viewer --scene-input scene.json `
  --grown-review-mode generated `
  --grown-review-library library.forest --grown-review-source SOURCE_A `
  --grown-review-second-source SOURCE_B --grown-review-level middle `
  --grown-review-batch-control ordinary --output generated-plates
```

Do not pass a specimen encoding role. Generated mode uses the live Address path,
not native authoring. Its plates are `grown-generated-context`,
`grown-generated-first-source`, `grown-generated-second-source`,
`grown-generated-ground` and `grown-generated-root`; use `--view` to select
them. Source views fit original source envelopes at actual producer-mapped
roots. Ground and root views reuse the existing native scene cameras. The root
camera must join its focus to an unchanged original physical tree. All views
keep vista terrain visible and use held natural terrain support.

The original generated trees and rocks retain their physics identities,
collider-centred transforms, static bodies, layers and terrain-scene ownership.
Each tree's visual child removes the collider-centre offset once. The census
checks every original obstacle and every source part, including offscreen parts.
It checks the live cache, actual stream attachment, visual hierarchy, mesh,
material, conservative bounds, shadow and batching policies again through the
final screenshot callback.

The draw observer remains the same ordinary renderer observer. It selects its
required members from the held camera's actual visibility after the complete
census check. Each visible source partition must have its exact root/tag set in
one shared command. Both actual sources require multi-root commands. All six
installed closures must share the four role-specific source handles. Successful
submissions retain the actual prepared GPU allocation IDs and sizes; changed or
missing allocations invalidate the held proof. This does not inspect opaque
bind-group entries or source-buffer storage bytes.

Generated held-pose controls first freeze the uncontrolled visible demand, then
apply the requested fault. No submission is eligible in the fault-arming frame.
`hidden-last-root`, `missing-last-tag`, `forced-singletons` and `changed-level`
target actual visible entities or the actual scene request. Hiding a root never
shrinks required membership. Frozen demand and application receipts are saved as
`grown-fault-demand.json` and `grown-fault-applied.json`. Wrong scene owner and
parented-original-root controls remain original-batch startup checks. The
generated singleton control also marks each unchanged `Mesh3d` component
changed. This asks Bevy to requeue the existing material bin with its new
batching marker; changing that marker alone does not invalidate a retained bin.
Mesh handles and assets remain unchanged. Its rejection requires an actual split
or nonindirect owned draw, not merely the presence of the marker.

The bounded GPU proof admits at most 4,096 selected tree/terrain members per
frame. A larger selected-level census rejects rather than truncating roots or
parts. The immutable hierarchy census also covers inactive installed levels.
Middle is the initial two-source Harz trial; Full can exceed this proof limit.
Recipe vista trees and named Recipe diagnostic specimens are excluded at their
producers. Actual terrain, grass, ordinary rocks and original tree roots remain.
The missing distant grown-tree producer is an explicit limit: these captures are
not complete visible-area arrival evidence, species calibration, weather
support, continuous moving LOD, browser acceptance or physical-memory
measurements. Current Grown requests require clear weather without snow.

## Adaptive selection in the tactical presenter

A grown scene request carries `LevelSelection::Fixed` or `Adaptive`. Adaptive
roots install their three immutable level groups under the same visual frame.
After the gameplay camera and transforms update, the existing streamer selects
one group using the shared physical-pixel projection and 15-percent hysteresis.
The source envelope belongs to the actual selected botanical model. Switching
levels changes visibility without creating meshes, materials or source buffers.
Missing or invalid camera input leaves all groups hidden and cannot provide a
ready selection. The inspector exposes stable hierarchy ownership separately
from the current selected level. The fixed diagnostic keeps its original flat
part hierarchy.

This adds entities for inactive groups. It does not establish a memory or
arrival budget. An explicit `--grown-review-level adaptive` capture checks
generated roots through the finite checkpoint path. A successful checkpoint
requires its actual first transition submission; its settled image is a separate
appearance check. Coarse geometry retains all botanical records and is not a
distant forest representation.

### Adaptive checkpoint evidence

Pass `--grown-review-level adaptive` with generated mode and the same admitted
bank and two source identifiers. The implicit warmup proves every root selects
Coarse. The subsequent cameras bracket both source-library pixel thresholds,
including approach, retreat, hysteresis holds and return. Supported eyes use the
existing natural terrain clamp. Each checkpoint records measured per-root pixel
radius, prior level, actual selected level and owning group. Selecting a later
`--view` retains its entire preceding sequence.

The same capture configuration system runs before the adaptive selector and
visibility update. An ordinary non-warmup checkpoint binds its first extraction
serial, actual extracted camera and selected GPU membership. Missing source
buffers, mesh/material pipelines or successful commands in that frame fail the
checkpoint. A later ready frame cannot replace it. The current camera join
admits the standard gameplay camera with no clip-from-world override; it does
not inspect GPU view-uniform bytes. Screenshot callbacks check held ownership,
selection and tags, but the settled PNG is not an exact first-frame image.

Scene initialization prepares the actual required detail-terrain color
permutations, including their existing depth bias, through Bevy's shared
specialization cache even when the initial camera cannot see the patch. The
generated witness uses the camera's actual render-entity mapping and waits for
that scene/camera acknowledgement before its first
warmup configuration. Later transitions receive no readiness grace. Per-pose
evidence records the prepared terrain pipeline identity. This adds no hidden
draw or forced tree level; all required preparation belongs inside an inclusive
arrival measurement. It does not establish prepass/shadow or pixel readiness.

All installed level parts receive nonzero diagnostic tags, including inactive
parts. Their identities and tag presence remain checked through extraction and
the final callback. Retained tag admission is separate from the unchanged
4,096-member active GPU limit: it is the actual installed tree-part count plus
one per-frame background bound for each finite checkpoint. The report retains
that derivation and the complete immutable hierarchy census. Unexpected
submitted tags reject stray inactive draws.

The `missing-inactive-tag` control removes a real tag from another installed
level after freezing visible demand. It requires generated adaptive mode. All
intentional held-demand faults use a separate fault observation requirement;
their fault-arming frame is withheld as before. They do not claim ordinary
first-transition success. Ordinary adaptive checkpoints retain the strict first
frame requirement. These diagnostics establish neither continuous camera cadence
nor distant-tree representation, species calibration, browser runtime, physical
memory or complete-area arrival performance.

## Private specimen input and commands

Supply a checked `library.forest`, its actual botanical `PlantId`, and a
tactical scene input. The identifier is neither a model ordinal nor a placement
ID. The selected model must contain both branch and leaf records. Keep source
generation evidence separately: decoding cannot establish how records were
produced, biological age, or species calibration.

The library must use `FORESTL3`, with its exact canonical topology revision. It
contains source records and model metadata, not generated address meshes.
Regenerate older libraries from their source; this tool has no older-format
decoder. Both constructions build only the live triangle prefix for each part.
The library digest changes with the new payload, so regenerate any populations
bound to that library as well.

Build the native viewer with `grown-review`, then use a fresh process and output
directory:

```powershell
cargo build --locked -p adventuresim-tactical-client `
  --bin tactical-scene-viewer --features grown-review

# Use the executable in the configured Cargo target directory.
tactical-scene-viewer --scene-input scene.json `
  --grown-review-mode specimens `
  --grown-review-library library.forest --grown-review-source SOURCE_ID `
  --grown-review-role candidate --grown-review-level full `
  --grown-review-batch-control ordinary `
  --output shared-plates
```

Specimens require mode, library, source, role, level, control and scene input.
They conflict with explicit fixtures, profiles, source authoring, benchmark
modes and scene overrides. Use `--view grown-middle-interior` to select one
intended-distance plate, or omit `--view` to capture the finite catalog. Warmup
is implicit.

Every level and encoding uses the same source-only camera catalog. The
`grown-shared` close plate and warmup fit the union of the three original source
envelopes. The other five plates use each original source envelope's projected
radius, with the renderer's physical-pixel projection and level selection
policy. Candidate mesh bounds never determine framing.

| Plate | Target largest source radius |
|---|---|
| `grown-full-side` | 1.05 times the source's Full threshold |
| `grown-middle-full-side` | 0.80 times the Full threshold |
| `grown-middle-interior` | Geometric mean of Full and Middle thresholds |
| `grown-middle-coarse-side` | 1.05 times the Middle threshold |
| `grown-coarse-side` | 0.80 times the Middle threshold |

The factors position review plates around the existing transitions; they are not
new runtime thresholds. The report records all three roots' actual source
proxies and the level each would select from every previous level. Roots can
straddle a transition. Static plates do not demonstrate adaptive movement or
hysteresis over time. A supported camera can still have obstructed sight lines;
inspect the actual image before accepting its usefulness.

Cameras resolve once after the captured natural scene and its vista support are
admitted. Every eye uses the presentation owner's stitched terrain height, with
standing-eye clearance. Unsupported eyes and missing retained terrain rings fail
startup. Intended-distance plates display actual vista terrain. The close plate
remains a local geometry diagnostic. This bounded witness uses natural terrain
support; urban support is not admitted.

Observation and final screenshot checks retain the actual scene entity,
environment, vista revision, chunk membership and final eye-height samples. They
also require the actual physical viewport to match the fitting viewport. These
checks bind camera support; they do not seal every terrain asset byte or prove
that a terrain draw completed. Separate material-readiness and ordinary GPU
membership checks cover the visible terrain submissions.

The candidate uses real positions, normals and texture coordinates authored on a
separate compute device. The reference role evaluates original integer vertex
addresses in the vertex shader. Both share branch/leaf surface functions and
tactical lighting. Use `--grown-review-role reference` for that diagnostic
counterpart with the same level. Its meshes are built directly from checked
integer addresses and live triangle prefixes, with placeholder position, normal
and texture-coordinate channels. It does not create a compute device or expand
attributes only to discard them. The ordinary geometry and materials are
available with the environment crate's `prepared` feature on native and Wasm
targets; native compute expansion additionally needs `grown-authoring`.
Compiling for Wasm alone does not demonstrate browser rendering.

Geometry owns its actual vertex encoding and immutable selected level;
installation cannot choose a different interpretation. Materials derive their
encoding and record-address stride from that owner. Part identity and the final
capture checks include the level. Each level can partition its source records
differently under the allocation limit, so part counts can differ.

Fewer branch spans straighten the sampled curve. Fewer leaf blades change both
attachment and blade size. This preserves the existing renderer's approximation
policy; it does not establish visual suitability at a given distance. Compare
reference and candidate at the same level and camera for conversion fidelity,
then compare adjacent levels at the same intended-distance camera for quality.
The current close plate is a geometry diagnostic, not distant LOD acceptance.

Both constructors reject meshes above explicit per-part and total payload limits
before allocating their channels. Native expansion also applies its device's
compute/storage limits. Its device is released before the tactical renderer
starts. The two stages may select different adapters or backends; inspect both
receipts. Do not borrow an active renderer for blocking authoring readback.
Installation errors are terminal; partially installed assets are not reusable
results and the tool supplies no replacement-source fallback.

## Scene and ownership

The native host binds its original generated obstacle batch to the actual
terrain-scene entity. Before isolation, it checks each original obstacle's
identity, kind, unparented collider-centred transform, static body, collision
layers and collider presence. The report retains this original batch separately.
Those obstacles are then removed for the private layout below. This check does
not mean that grown meshes use the generated physical roots or establish
ownership for replicated multi-scene gameplay.

The `changed-scene-owner` and `parented-original-root` controls corrupt one
actual generated obstacle before this check. They must fail before private
layout installation or any held-pose GPU proof. They are startup rejection
controls, rather than controls that wait for an intended-distance pose.

The destination roots use authored offsets at the scene centre and twelve metres
to either side. Each samples its own terrain support and retains identity scale
and yaw. Source growth on other terrain is not adapted to the destination slope.
Unrelated scene obstacles, playable ground scatter, vista trees, vista rock and
grass scatter, and named review specimens are removed. Shared playable, detail
and vista terrain remain. This isolated layout is not a complete forest scene.

Upload the admitted bank once per presenting Bevy asset world with
`GrownBankAssets::upload`. Retain its returned `Arc` and pass it to every
`GrownAssets::install` for that bank, across models, levels and encodings. Each
installation checks the actual library identity and asset world before creating
its meshes or materials. Source handles are shared through this explicit owner;
uploading a second owner deliberately creates separate assets. There is no
automatic global lookup or replacement-source fallback.

`GrownAssets` retains that shared bank owner, source identity, mesh partitions,
selected level and ordinary materials. Placement identity is separate from
botanical source identity. Source root coordinates are removed during library
authoring, then destination root transforms are applied once. Do not apply
collider half-height normalization to these meshes.

Attach supplied bounds with `NoAutoAabb`. Address evaluation needs its original
source-conservative bounds; the candidate uses actual mesh bounds. Normal
frustum culling remains enabled. The positive control leaves automatic batching
enabled for tree parts. Shared terrain is deliberately unbatchable so its
individual material commands remain identifiable.

Meshes and source-buffer uploads use render-world extraction. The tool does not
retain diagnostic CPU mesh copies or compare full vertex arrays every frame. The
admitted bank remains retained; this does not establish physical RAM or GPU
memory use. Both materials provide forward and prepass shader paths. Analytic
leaf outlines retain fractional forward multisample coverage. Depth and shadow
fragments discard source alpha below 0.02 and otherwise write binary coverage.
This explicit cutout policy still needs context-specific visual review.

## GPU proof and rejection controls

The observer wraps successful main-pass material commands and snapshots actual
indirect arguments and compacted GPU mesh-instance data. Every shared tree part
must appear in exactly one command with all three intended instances. Tags join
actual GPU rows to distinct root entities, exact transforms, mesh allocations
and material slots. Three separate successful draws cannot pass. Visible terrain
must also match its held command bindings. The camera, inventory, tags and
renderer bindings remain held through the final screenshot callback.

Indirect-argument offsets and batch-set indices belong to each recorded frame.
Bevy rebuilds those arrays, so their absolute addresses may move between held
frames. The later-frame guard preserves the exact multiset of commands that can
draw held tree or terrain members, plus commands from their known held
representatives. It holds pipelines, representative entities, materials, mesh
bindings, positive command-span lengths and count-source modes. Unrelated
material draws may finish preparation independently. Direct and dynamic-uniform
dispatches remain exact. The original snapshot still decodes all recorded draws.
Each original receipt and storage snapshot retains its actual frame-local
addresses for decoding. Exact GPU membership is established for that initial
recorded snapshot; later semantic-command checks do not decode every frame or
establish exact screenshot-frame membership.

The required member set does not shrink to match surviving GPU output. Use
explicit controls in separate fresh processes:

- `forced-singletons` disables automatic batching for the tree parts. It must
  fail the shared-command requirement.
- `hidden-last-root` hides the third root after warmup. It must fail the full
  three-root GPU membership requirement.
- `missing-last-tag` removes a held part's tag after warmup. It must fail the
  tag ownership check.
- `changed-level` changes the review selection after warmup while keeping the
  installed geometry and materials. It must fail the held source/level check
  before the next pose can authorize a GPU proof.

`grown-runtime.json` records the render adapter and depth planes.
`grown-review.json` records source metadata, held cameras, complete owned
inventory and GPU membership results. Raw snapshots, command receipts and proofs
are saved under `gpu-batches/`. The manifest records the actual fixed-level
capability, separate from adaptive gameplay tree presentation.

The manifest records equal settled raw-readback hashes. Normal output saves the
final RGB PNG; a settling mismatch can also save retry PNGs. It does not
guarantee independently decodable files for the accepted raw pair or retain
alpha. Compare reference and candidate images directly and report differences
rather than assuming pixel parity.

Diagnostic copies, readbacks and serialization add work. These runs are untimed
correctness evidence. Main-color membership does not validate shadow or prepass
membership, GPU vertex/source-buffer bytes, exact screenshot-frame timestamps,
moving cameras, browser behavior, adaptive detail or complete visible-area
arrival. Performance runs must measure their complete lifecycle separately.
